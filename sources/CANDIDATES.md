# Candidate schema sources

Other places that describe reference genomes, beyond the ten sources already being collected (galaxy, refgenie, fhr, ncbi, ena, ensembl, ucsc, nfcore, bioconductor, ga4gh). Links were checked on 2026-11-17. A few hosts (gatk.broadinstitute.org, support.terra.bio, edamontology.org, 10xgenomics.com) block scripted checks, but the pages exist.

## High priority

| Name | Link | What it is | Why it matters for refmeta |
|---|---|---|---|
| RDA FGA-WG `GenomeAssembly` | https://fairtracks.github.io/fga-wg/GenomeAssembly/ | LinkML schema from the RDA FAIRification of Genomic Annotations Working Group. Its `GenomeAssembly` class has `seqcol_digest`, `seqcol_ordered_coord_system`, `seqcol_unordered_coord_system`, `accessions`, `aliases`. | This model is the closest to refmeta. It already names the collection level by its seqcol digest and keeps accessions and aliases apart. refmeta should line up with it rather than compete. |
| Legacy GA4GH Reference API (ga4gh-schemas `ReferenceSet`/`Reference`, also Google Genomics v1) | https://schemas.readthedocs.io/en/latest/schemas/references.proto.html | `ReferenceSet`: id, name, order-independent `md5checksum`, `ncbiTaxonId`, `assemblyId`, `sourceUri`, `sourceAccessions`, `isDerived`. `Reference`: length, md5checksum, name, sourceUri, sourceAccessions, `isDerived`, `sourceDivergence`. | Direct ancestor of seqcol. It already split the assembly name from the set digest and flagged derived sets (such as analysis sets). It checks whether refmeta's three levels fit an earlier GA4GH design. |
| IGV genome JSON and hosted genome list | https://igv.org/doc/igvjs/Reference-Genome/ (list: https://igv.org/genomes/genomes.json; repo `igvteam/igv-data`) | Genome config with `id`, `name`, `fastaURL`, `indexURL`, `twoBitURL`, `chromSizesURL`, `aliasURL`, `cytobandURL`, `chromosomeOrder`, `blatDB`, `tracks`. The hosted list holds records for about 100 genomes. | A heavily used "copy" record. Its `aliasURL` points at UCSC chromAlias files. It is simple to convert in both directions and gives real records for both anchor genomes. |
| JBrowse 2 assembly config | https://jbrowse.org/jb2/docs/config_guides/assemblies/ | Assembly `name`, `aliases`, `displayName`, `sequence` adapter (IndexedFasta, BgzipFasta, TwoBit), `refNameAliases` (RefNameAliasAdapter for chromAlias, NcbiSequenceReportAliasAdapter for NCBI sequence reports), `cytobands`. | The second major browser config. It has assembly-level aliases plus pluggable sequence-name alias sources from both UCSC and NCBI, which match refmeta's alias model. |
| HPRC assembly index (Release 2) | https://github.com/human-pangenomics/hprc_intermediate_assembly/tree/main/data_tables | CSV `assemblies_release2_v1.0.index.csv`: `sample_id`, `haplotype`, `phasing`, `assembly_method`, `assembly_method_version`, `assembly_date`, `assembly_name`, `source`, `genbank_accession`, `assembly_md5`, `assembly_fai`, `assembly_gzi`, `assembly` (S3 URL). | One row covers all three refmeta levels: the GCA accession, a per-haplotype collection, and an S3 copy with checksum and index files. It is the test case for hundreds of personal haplotype assemblies. |
| PanSN-spec | https://github.com/pangenome/PanSN-spec | Naming rule `sample#haplotype#contig` built into sequence names in FASTA, GFA, and VCF. | It puts sample and haplotype inside sequence names. refmeta needs a rule for splitting and joining such names and for tying them to collections. |
| GFF3 and GTF header lines | https://github.com/The-Sequence-Ontology/Specifications/blob/master/gff3.md | GFF3 `##genome-build <source> <name>` and `##sequence-region <seqid> <start> <end>`. Ensembl GTFs add `#!genome-build`, `#!genome-version`, `#!genome-date`, `#!genome-build-accession` (e.g. GCA_000146045.2), `#!genebuild-last-updated`. | Annotation files carry the assembly name, accession, and sequence lengths in their headers. refmeta can read these to tell which collection an annotation was made for. |
| INSDC flat-file headers (GenBank/EMBL/DDBJ) | https://www.ncbi.nlm.nih.gov/genbank/structuredcomment/ | Per-sequence records: `DBLINK` (BioProject, BioSample, Assembly), `source` qualifiers (`/chromosome`, `/organelle`, `/plasmid`), and the `##Genome-Assembly-Data-START##` structured comment (Assembly Method, Assembly Name, Genome Representation, Expected Final Version, Genome Coverage, Sequencing Technology). | Gives each sequence's role (chromosome, organelle, plasmid) and its link to the assembly, both of which refmeta needs at the sequence level. The structured comment adds assembly provenance. |
| Bioregistry / identifiers.org prefixes | https://bioregistry.io/registry/insdc.gca | Standard CURIE prefixes, regex patterns, and resolvers: `insdc.gca`, `insdc.gcf` (identifiers.org uses `refseq.gcf`), `ncbi.assembly`, `refseq`, `ensembl`, and more. | refmeta needs one way to write identifiers across all sources (for example `insdc.gca:GCA_000001405.15`). Bioregistry already defines the prefixes and their patterns. |
| GATK resource bundle / Broad references (WARP structs, Terra) | https://github.com/broadinstitute/warp/blob/develop/structs/dna_seq/DNASeqStructs.wdl | Public bucket `gs://gcp-public-data--broad-references` (`hg38/v0/Homo_sapiens_assembly38.*`). WDL `ReferenceFasta` struct: `ref_dict`, `ref_fasta`, `ref_fasta_index`, `ref_alt`, `ref_sa`, `ref_amb`, `ref_bwt`, `ref_ann`, `ref_pac`. Terra uses `workspace.referenceData_*` attributes, and Cromwell uses reference-disk manifests. | The most-used reference bundle in WDL and Terra workflows. It is a file-bundle "copy" record similar to a refgenie asset, and its hg38 is a derived collection (adds alt, decoy, and HLA contigs) that refmeta must name correctly. |
| genomepy | https://github.com/vanheeringen-lab/genomepy | Python tool that searches and installs genomes from Ensembl, UCSC, NCBI, GENCODE, or a plain URL. For each genome it installs, it writes a `README.txt` recording the provider, accession, taxonomy id, original name, source URLs, and options used. | It already solves a small version of refmeta's problem with one search across four providers. Its provider adapters and README fields form a ready-made crosswalk to compare against. |

## Medium priority

| Name | Link | What it is | Why it matters for refmeta |
|---|---|---|---|
| AGP v2.1 | https://www.ncbi.nlm.nih.gov/genbank/genome_agp_specification/ | Tab format that describes how components (contigs, WGS pieces) join into objects (scaffolds, chromosomes), with typed gaps and linkage evidence. | Describes how an assembly is built below the sequence level. INSDC and GRC assemblies ship it. Useful for component accessions and for unlocalized or unplaced sequences. |
| GFA 1.1 walk (W) lines | https://gfa-spec.github.io/GFA-spec/GFA1.html | `W` lines: `SampleId`, `HapIndex`, `SeqId`, `SeqStart`, `SeqEnd`, walk. | Graph pangenomes store each haplotype's sequences as walks named the PanSN way. refmeta needs these to link a graph to the collections inside it. |
| GoaT (Genomes on a Tree) | https://goat.genomehubs.org/ | GenomeHubs search engine and API (`/api/v2`) with 30+ assembly attributes (`assembly_level`, `assembly_span`, contig and scaffold N50, BUSCO, and more) across eukaryotes. It is the official EBP status tracker. | It pulls biodiversity assemblies (EBP, DToL, VGP, ERGA) into one record shape, so one adapter covers many projects. |
| Hail `ReferenceGenome` | https://hail.is/docs/0.2/genetics/hail.genetics.ReferenceGenome.html | JSON: `name`, `contigs` [{name, length}], `xContigs`, `yContigs`, `mtContigs`, `par` (pseudoautosomal regions). | Adds sequence-role data (sex chromosomes, mitochondrion, PARs) that most schemas lack. gnomAD uses it. |
| HCA `reference_file` schema | https://github.com/HumanCellAtlas/metadata-schema/blob/master/json_schema/type/file/reference_file.json | JSON Schema with `ncbi_taxon_id`, `genus_species`, `reference_type`, `assembly_type` (primary, complete, or patch assembly), `reference_version` (e.g. "GencodeV27"). `analysis_file` has a `genome_assembly_version` enum (GRCh38, GRCm39, ...). | Shows how a large data portal labels the reference it used. Its `assembly_type` enum is a distinction refmeta's collection level must be able to express. |
| ENCODE-family portal reference objects (SMaHT, IGVF, ENCODE) | https://submitr.readthedocs.io/en/stable/object_model/types/reference_genome.html | SMaHT `ReferenceGenome`: `identifier`, `title`, `code`, `version`, `genbank_assembly` (^GCA_), `refseq_assembly` (^GCF_), `aliases`, `files`, `url`. IGVF and ENCODE file objects carry an `assembly` enum (GRCh38, GRCm39, custom) and a `transcriptome_annotation`. | These portals share software and treat the reference as an object with GCA/GCF fields. Their enums act as a shared controlled list of assembly names. |
| Beacon v2 and Phenopackets v2 assembly fields | https://phenopacket-schema.readthedocs.io/en/2.0.0/file.html | Beacon `assemblyId` (e.g. GRCh38) with `referenceName` (RefSeq accession recommended). Phenopackets `File.fileAttributes.genomeAssembly` (the spec text says `genomicAssembly`). Beacon docs: https://docs.genomebeacons.org/variant-queries | GA4GH clinical standards outside seqcol/refget that name assemblies with free text. refmeta could turn those strings into collections. |
| GA4GH DRS | https://ga4gh.github.io/data-repository-service-schemas/ | `DrsObject`: `id`, `self_uri`, `size`, `checksums` [{type, checksum}], `access_methods`, `aliases`, `version`. | The copy level as a GA4GH standard. refget already serves FASTA through DRS (`FastaDrsObject`), so refmeta's copy record should map to it directly. |
| CRAM reference registry / htslib `REF_PATH` | https://www.htslib.org/doc/reference_seqs.html | EBI service that returns a sequence by MD5 or SHA1. htslib's `REF_PATH`/`REF_CACHE` layout (`%2s/%2s/%s`). SAM `@SQ` `M5` and `UR` tags. | The sequence lookup most CRAM users rely on today. refmeta's sequence records should keep MD5 next to the refget digest so they connect to it. |
| MIxS / GSC MIGS checklists | https://w3id.org/mixs/0010002/ | Genome checklist fields: `assembly_name`, `assembly_software`, `assembly_qual` (Finished, High-quality draft, ...), `number_contig`, `compl_score`. Used in BioSample and ENA sample records. | Standard words for assembly provenance and quality that INSDC submissions reuse. |
| Wikidata genome assembly items | https://www.wikidata.org/wiki/Property:P4333 | Class "genome assembly" (Q55433859). Items such as GRCh38 (Q20966585) and T2T-CHM13 (Q124316437). Properties P4333 (INSDC/RefSeq assembly accession), P659 (genomic assembly, used on gene and variant positions), P2249 (RefSeq genome ID). | An open linked-data hub that already ties assembly names to accessions and species. A cheap source of name-to-accession aliases, and a place to publish refmeta mappings. |
| Genome Warehouse (GWH, CNCB-NGDC) | https://ngdc.cncb.ac.cn/gwh/ | Non-INSDC assembly archive with its own accessions (GWHAAAA00000000), linked BioProject and BioSample records, and an API. | Many plant and animal assemblies exist only here. refmeta's assembly level must accept accessions that are not GCA/GCF. |
| 10x Cell Ranger reference package | https://www.10xgenomics.com/support/software/cell-ranger/latest/analysis/inputs/cr-3p-references | `cellranger mkref` writes `reference.json` with the genome name, FASTA and GTF hashes, input files, mkref version, and a reference version (e.g. 2020-A). Cell Ranger DNA and ARC also mark primary, sex, and non-nuclear contigs. | A very common prebuilt reference bundle in single-cell work. It carries its own version string and content hashes, so it is a copy-level record refmeta should read. |
| FASTA header and file-name conventions | https://ftp.ensembl.org/pub/current_fasta/homo_sapiens/dna/README | Ensembl headers such as `>1 dna:chromosome chromosome:GRCh38:1:1:248956422:1 REF` (coordinate system, assembly, region), file names like `species.assembly.type.idtype.id.fa.gz`, and NCBI deflines with accessions. | Often a FASTA file is the only metadata a user has. Parsing headers and file names can recover the assembly and each sequence's role. Check for overlap with `sources/ensembl/`. |

## Low priority

| Name | Link | What it is | Why it matters for refmeta |
|---|---|---|---|
| Earth BioGenome Project assembly standards | https://www.earthbiogenome.org/report-on-assembly-standards | "x.y.Qz" quality notation (e.g. 6.C.Q40: megabase contigs, chromosome-scale scaffolds, Q40 accuracy), plus BUSCO and false-duplication thresholds. | These are quality labels, not identity. They could become optional quality fields on the assembly level. |

| Go Get Data (GGD) | https://gogetdata.github.io/ | Conda data recipes whose `meta.yaml` holds species, genome-build, data-provider, data-version, file-type, and genomic-coordinate-base. | Shows a provider + build + version naming scheme. The project looks quiet. |

| UniProt proteomes | https://www.uniprot.org/help/proteome | Proteome entries cite the source genome assembly (GCA accession and provider), genome representation, and components. | Shows downstream resources pinning to an exact assembly version, sometimes the Ensembl one and sometimes the RefSeq one. |
| dpryan79 ChromosomeMappings | https://github.com/dpryan79/ChromosomeMappings | Plain tables that map chromosome names between UCSC, Ensembl, and GENCODE for many genomes. | Ready-made alias data for testing refmeta's name mapping against UCSC chromAlias. |

| GOLD (JGI) | https://gold.jgi.doe.gov/ | Genomes OnLine Database: project and analysis-project records that link to assemblies, mostly microbial. | Mostly microbial, so it matters little for reference genomes. |

## What to add next

I would add these five next. **RDA FGA-WG `GenomeAssembly`** comes first because it already builds on seqcol digests, accessions, and aliases, so refmeta should match it before its own model settles. **HPRC Release 2 assembly index** (with PanSN-spec) is the cleanest real example of all three levels in one record, and it covers the haplotype assemblies that the current ten sources mostly miss. **IGV genome JSON and JBrowse 2 assembly config** are the "copy" records people edit most often, have simple fixed fields, and include alias files, so they are quick, useful targets for the converter. The **legacy GA4GH `ReferenceSet`/`Reference`** schema is GA4GH's earlier try at the same model (assembly id, order-independent set checksum, `isDerived`), and refmeta should be able to explain how it differs. **GATK/Broad references (WARP `ReferenceFasta`)** is the most-used reference bundle in WDL and Terra workflows and maps closely to refgenie assets. Separately, Bioregistry prefixes should set how refmeta writes all identifiers, even though Bioregistry is not a source to collect.
